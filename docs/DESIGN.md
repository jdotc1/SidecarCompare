# SidecarCompare design

## Outcome and boundaries
A small, local-only macOS utility for Jeff's MRI research workflow: explicitly select two dcm2niix/BIDS-style JSON sidecars and inspect acquisition-metadata differences before downstream analysis. Target macOS 15+, Swift 6, SwiftUI-first, no third-party runtime dependency. Read-only inputs; memory-only sessions; no network, telemetry, bookmarks, recent-files database, DICOM conversion, image rendering, metadata correction, directory scanning, or BIDS inheritance resolution. Generic JSON objects are accepted, but the application never certifies BIDS validity, de-identification, image alignment, scan equivalence, clinical suitability, or radiomics readiness.

## Interaction
One intentionally single-window workspace owns the comparison; closing it quits and discards the session. This avoids cross-window source-protection ambiguity. A same-source warning detects repeated file identities or selected paths without equating independently copied files. Two compact file wells (A/reference and B/comparison) support a native Open panel and one-file drops. Swap and Clear are explicit actions. A native table shows status, JSON Pointer, A, B, and known canonical unit. Search, differences-only, and category controls affect presentation only. Differences-only retains within-tolerance changes. A selected-row inspector shows complete types, bounded value previews, units, and interpretation notes. Toolbar and menu commands expose opening, swapping, resetting, summary copying, export, and built-in synthetic examples. Semantic fonts/colors, native selection, keyboard navigation, labels independent of color, resizable table columns, and Light/Dark compatibility are requirements.

## Comparison contract
Top-level objects only. Object-member order does not matter; arrays are positional, never sorted or treated as sets. Missing, null, boolean, string, number, empty object, and empty array remain distinct. Leaf paths are RFC 6901 JSON Pointers. On container type change, emit one row at the changed container instead of misleading child additions/deletions. A missing subtree is represented at its root. Identical empty containers remain visible. Exact decimal numeric equality is mathematical (1, 1.0, 1e0 are equal), independent of Double rounding. Preserve the original numeric token for inspection/export. Strings compare decoded UTF-8 without case folding or Unicode normalization. Reject duplicate or canonically equivalent object keys instead of silently dropping one.

Statuses: Equal, Within tolerance, Changed, Type changed, A only, B only. Exact is the default. An optional dimensionless relative tolerance is restricted to numeric leaves of curated top-level MRI quantity fields (and immediate numeric arrays for fields permitting arrays); unknown/vendor-nested numbers and counters remain exact. The rule is abs(B-A) <= r * max(abs(A),abs(B)); no absolute tolerance, no implicit unit conversion, no absolute tolerance floor (zero versus nonzero is outside tolerance when r < 1), and no recommendation of a scientific tolerance. Classify using exact decimal arithmetic rather than floating-point comparisons. A raw delta is informative, not a clinical judgment.

## Units and metadata policy
The catalog is a curated, versioned subset, not a BIDS validator. It distinguishes BIDS fields from dcm2niix extensions. Time fields such as EchoTime/RepetitionTime are interpreted in seconds; an optional milliseconds display is a presentation transform only. Other fields use degrees, tesla, millimeters, MHz, or Hz as documented. Unknown fields remain unit-unspecified; global `Units` never changes acquisition-field units. No guessing from magnitude, DICOM conventions, ProtocolName, or nested matching field names. Invalid known shapes receive notes and are compared exactly. Every raw field remains available.

## Security and limits
Accept UTF-8 JSON (optional leading BOM), <= 2 MiB, <= 20,000 JSON values, nesting <= 32, decoded string <= 65,536 UTF-8 bytes, key <= 512 bytes, numeric token <= 256 characters, explicit exponent magnitude <= 400. Limits are checked before expensive work where possible and reported clearly. Reject comments, trailing commas/content, malformed numbers, invalid escapes/UTF-8, lone surrogates, duplicate keys, and non-object roots. Only regular local files are read; nonblocking POSIX open plus descriptor validation avoids FIFO/device hangs. Reading, parsing, and comparisons run off the UI actor and support cancellation. Generation tokens prevent superseded work from publishing results. Comparison expansion has separate limits: 20,000 output rows, 2,048 UTF-8 bytes per JSON Pointer, and 2 MiB aggregate pointer bytes. Exceeding a comparison budget rejects the whole result; rows are never silently truncated.

No document values or paths in logs/errors. The app never adds selected-file names or paths to a report. Full reports preserve all original metadata, including filenames or paths already embedded in input fields; they may therefore identify people. Summary exports contain counts/policy only, no input keys or values; detailed exports require explicit acknowledgment that metadata can identify people. Detailed export is NOT de-identification. Atomic report writing refuses source paths, symlinks, and known hardlink identities. Source hashes and byte counts are not exported as identity side channels. Sources can change externally: comparison is an in-memory snapshot, not live synchronization. Reads do not lock inputs; avoid modifying a file during import, because a coherent snapshot under concurrent mutation is not guaranteed.

## Structure
`SidecarCore`: bounded parser, exact decimal arithmetic, field catalog, recursive comparator, deterministic reports, bounded file I/O, observable session with injected async loading.
`SidecarCompare`: SwiftUI window, native table/inspector, drop/open adapters, export sheet and native save panel, focused menu commands.
`sidecar-compare`: small optional CLI using the same core, useful for independent black-box tests and reproducibility.
`script`: SwiftPM app-bundle staging, test/smoke/build-and-run; no runtime Python. Python is used only by repository verification scripts.

## Acceptance
Parser/comparison/report/session/file-I/O tests must pass under Swift 6 with warnings treated as errors. Deterministic synthetic cases and a Python Decimal/JSON oracle cross-check must pass. On macOS, build the GUI, stage/sign the development bundle, launch it and run the manual keyboard, drag/drop, accessibility, privacy, cancellation and export acceptance list. Linux testing cannot satisfy this native gate. No publish/push, Developer ID signing, notarization, or distribution claim occurs in this record.

## Comparison review controls

Status filtering composes with search/category/differences-only. Counts in the status picker describe the entire loaded comparison. Selecting Equal turns off Differences only; enabling Differences only clears an Equal status filter. Hidden selections clear. Clicking table headers sorts ascending/descending; A/B sort numbers by exact decimal value and strings by decoded UTF-8 text, independently of display units. Stable row IDs break sort ties. Sorting preserves visible selection. Previous/Next Difference follows visible sort order, skips Equal, stops at the ends and opens the selected field in the inspector. With no selection, Next starts at the first visible difference and Previous starts at the last. Commands use Command-Option-Up/Down. Filters, sorting and selection never alter report contents.

Reload A/B explicitly rereads the current document's original selected URL through the existing loader. Preserve that URL's security-scope metadata; normalize paths only when checking identities/write protection. Reload is unavailable for URL-less examples, empty slots, session work and open import/export panels. Failed reload follows failed replacement semantics: remove old snapshot/comparison and direct Choose… recovery. No bookmarks, persistence, directory scanning or automatic watching is added.

Inspector value cards distinguish A/reference and B/comparison, label raw JSON and types, and summarize type changes A→B. Selectable raw previews wrap, start at512 characters, and independently expand to8192 with explicit counts/truncation notice. Row changes reset expansion. Missing is described as absent, distinct from JSON null. No numeric conversion or report truncation is introduced.

Numeric A/B presentation sorting uses JSONSortValue with existing exact-decimal magnitude/sign operations, without Double, tolerance, or display conversion. Ascending type order: missing, null, boolean, number, string, array, object. Strings use decoded UTF-8 order; containers use bounded compact-preview order.
